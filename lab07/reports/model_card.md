# Model card — ML-компонент «malignant проти benign» (ЛР № 7, версія моделі 1.0.0)

Ця картка доповнює [`handoff/MODEL_CARD.md`](../../lab06/handoff/MODEL_CARD.md) з ЛР № 6: метрики й причина вибору моделі
не змінювалися, додано умови відтворення та контракт програмного компонента.

## Призначення і користувач
Навчальний програмний компонент: за 30 числовими характеристиками запису FNA повертає **ймовірність класу malignant** і
прапорець класу за порогом 0.5. Користувач — експерт або студент, який готує ЛР № 8 (REST-сервіс). Результат —
підказка для ранжування записів для ручного розгляду, **не діагноз**.

## Заборонені застосування
Діагностика, скринінг, тріаж пацієнтів, будь-які клінічні чи інші значущі автоматичні рішення без експерта;
подання відповіді компонента як медичного висновку.

## Що саме в компоненті
| Параметр | Значення |
|---|---|
| Версії | модель 1.0.0 · схема 1.0 · конфігурація 1.0 · код 1.0.0 |
| Кандидат / family | `automl_seed42_trial10` / `lrl2` (L2-логістична регресія, C = 0.1, `class_weight=None`) |
| Конвеєр | `SimpleImputer(median, keep_empty_features=True)` → `StandardScaler` → `LogisticRegression(max_iter=5000, random_state=42)` |
| SHA-256 моделі | `b63381332edb446557779d0d3042cd4e3be973cbc9fd70a1682513fe9abc315b` |
| SHA-256 frozen decision | `62caba19558d196bdefb4b1b459d8d6ba1809f5d1f0aa9b7450401380a5a584c` (збігається з `lab06/handoff/decision.sha256`) |
| Позитивний клас | malignant (y = 1; у `load_breast_cancer` це `target == 0`) |
| Поріг | 0.5, правило `probability >= 0.5` → malignant; зміна порога = нова версія моделі |

## Дані
UCI Breast Cancer Wisconsin (Diagnostic), `sklearn.datasets.load_breast_cancer` (CC BY 4.0; W. Wolberg, W. Street, O. Mangasarian).
569 записів, 30 ознак; split ЛР № 6: train 455 / test 114 (stratified, seed 42), ID у `data/split_ids.csv`.
Діапазони в `configs/schema.json` — min/max лише за **train** (перевірено: збігаються з train, не збігаються з усім набором).
Набір уже використовувався в попередніх ЛР курсу, тому test «не торкнутий» лише в межах експерименту ЛР № 6.

## Метрики ЛР № 6 (test, один раз, поріг 0.5; не перераховувалися для підбору)
AP = 0.9966, ROC-AUC = 0.9977, F1 = 0.9756, precision = 1.0000, recall = 0.9524, Brier = 0.0234;
матриця помилок [[TN, FP], [FN, TP]] = [[72, 0], [2, 40]]. Вкладена CV (AP): 0.9942 ± 0.0058.
У ЛР № 7 ці значення **відтворено** rebuild-ом (AP різниця 0, матриця збігається), але не покращувалися.

## Вхідний контракт
Об'єкт JSON з 30 іменованими ознаками (порядок ключів неважливий; компонент сам ставить їх у порядок схеми).
Блокуються: відсутні/зайві ознаки, нечислові типи (рядки, bool, null), NaN/∞, від'ємні значення, значення, що переповнюють масштабування,
дубльовані ключі JSON, batch понад `max_batch_size` (1000). Значення поза train min/max **не блокуються** — відповідь містить `warnings`.

## Умови відтворення
Python 3.12, scikit-learn 1.9.0, numpy 2.2.3, scipy 1.15.3, joblib 1.6.0 (`requirements.txt`). Допуск: |Δp| ≤ 1e-12 для ймовірностей
(детермінована однопотокова LR; допуск обґрунтовано до запуску, лише для того самого середовища), 1e-9 для метрик.
Модель — pickle: завантажується тільки після збігу SHA-256 з `models/model_metadata.json`; хеш доводить незмінність байтів, а не безпеку чи якість.

## Відомі обмеження
- мала колекція (569 записів) з одного джерела; перенесення на інші лабораторії, сканери, популяції не перевірене;
- випадковий stratified split без інформації про пацієнтів чи час; залежність між записами не виключена;
- фіксований поріг 0.5 без калібрування; recall 0.9524 означає 2 пропущені malignant на 42 у test;
- діапазони train є діагностикою, а не гарантією коректності поза ними;
- немає моніторингу дрейфу, метрик експлуатації, автентифікації, обмеження частоти запитів, журналювання — це не production-ready;
- не перевірялися: якість за підгрупами пацієнтів і безпека pickle-пакета за межами SHA-256.
